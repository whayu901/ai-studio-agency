# n8n integration

n8n runs locally in Docker and **orchestrates**: it calls the app's endpoints in order. Every rule
(validation, character checks, claims, state transitions, approvals) stays in the app, which is
also the only persistent store for jobs. n8n never approves anything.

## Start

```bash
bash scripts/setup-local-env.sh                                   # once
docker compose -f n8n/docker-compose.yml --env-file n8n/.env up -d
bash scripts/n8n-import.sh                                        # import + activate, restarts n8n
```

Then in `web/.env.local`: `ACS_ORCHESTRATOR=n8n` (and `ACS_N8N_URL` if you changed the port), and
restart the dashboard. Check:

```bash
node web/scripts/n8n-smoke.mjs      # needs the dashboard running on port 3000
```

n8n UI: http://localhost:5678 (or the `N8N_HOST_PORT` you chose). On first visit n8n asks you to
create an owner account; that account and everything n8n stores live in the Docker volume
`acs-n8n_n8n_data`, which survives `docker compose down` / `up` and image upgrades.

> On this machine another n8n container (`n8n`) already used port 5678, so the studio's n8n runs as
> a separate Compose project `acs-n8n` on **5679**. The other container was not changed.

## Environment

| Variable | Where | Purpose |
|---|---|---|
| `N8N_ENCRYPTION_KEY` | n8n/.env | Encrypts n8n's stored credentials (random, generated) |
| `ACS_ORCHESTRATOR_TOKEN` | n8n/.env and web/.env.local (same value) | Shared secret on every webhook and callback |
| `ACS_APP_URL` | n8n/.env | How the container reaches the app: `http://host.docker.internal:3000` (inside Docker, `localhost` is the container itself) |
| `N8N_HOST_PORT` | n8n/.env | Host port, bound to 127.0.0.1 only |
| `GENERIC_TIMEZONE` | n8n/.env | e.g. Asia/Jakarta |
| `ACS_ORCHESTRATOR`, `ACS_N8N_URL` | web/.env.local | Turn n8n mode on, where to reach it |

`N8N_BLOCK_ENV_ACCESS_IN_NODE=false` lets the workflows read `ACS_APP_URL` / `ACS_ORCHESTRATOR_TOKEN`
with `$env`, so the exported workflow files contain **no credentials**. The trade-off: anyone who
can edit workflows in this n8n can read its environment. Keep it local and single-user.

## Workflows (`n8n/workflows/`, generated by `n8n/build_workflows.py`)

| File | Id | Webhook | Steps |
|---|---|---|---|
| A-original-creation.json | acsWfOriginal001 | `acs-original-creation` | Validate job → Creative brief → Script → Storyboard → Prompt compiler → Render readiness → Approval pending → Respond |
| B-reference-guided.json | acsWfReference01 | `acs-reference-guided` | Validate reference → Analyze reference manifest → Creative brief → Creative adaptation → Storyboard → Prompt compiler → Render readiness → Approval pending → Respond |
| C-production-review.json | acsWfReview00001 | `acs-production-review` | Receive render metadata → Attach generated video → Quality review pending → Respond |
| D-delivery.json | acsWfDelivery001 | `acs-delivery` | Validate approved job → Package assets → Generate delivery manifest → Mark delivered → Respond |
| E-error-handling.json | acsWfErrors00001 | Error Trigger | Record error in app (A–D name it as their `errorWorkflow`; it stays inactive by design) |

Each stage endpoint returns `done`, `skipped` (already done) or `halted` (waiting for a person:
brief approval, concept choice, script approval, …). Calling a workflow again after a person acts
continues from where it stopped.

## Callback endpoints (all `POST`, header `x-acs-token` required)

| Endpoint | Used by |
|---|---|
| `/api/orchestrator/jobs/:id/validate` | first node of A–D; also requires `x-acs-inbound-token` (the token the webhook call carried) before anything is linked |
| `/api/orchestrator/jobs/:id/stages/:stage` | `reference_analysis`, `brief`, `script`, `storyboard`, `prompts`, `await_render` |
| `/api/orchestrator/jobs/:id/renders/attach` | C |
| `/api/orchestrator/jobs/:id/approval-pending` | A–C end; reports what the job waits for |
| `/api/orchestrator/jobs/:id/package`, `/delivery-manifest`, `/delivered` | D |
| `/api/orchestrator/errors` | E |
| `/api/orchestrator/ping` | smoke test |

Headers n8n sends: `x-acs-execution-id` (`$execution.id`), `x-acs-run-key` (the submission's
idempotency key, links the execution to the run), `x-acs-idempotency-key`
(`<execution>:<step>`, a repeated call returns the stored response without running again).

## Reliability

- **Idempotency:** one submission per `<job>:<event>:v<version>`; repeats return the existing run.
- **No infinite retries:** HTTP nodes in A–D do not retry; a failure goes to Workflow E, which marks
  the job FAILED with the error and execution id (history kept). A person retries from the
  dashboard, at most `ACS_MAX_RETRIES` times; the job returns to exactly the state it failed in.
- n8n answers `200` with an empty body when a workflow fails before its Respond node; the app treats
  that as a failure.
- A webhook call without the token never reaches a job: `validate` rejects it before linking, and
  Workflow E's report for an unlinked execution is only logged.
- Traceability: every state change made by n8n carries its execution id (History tab and
  Settings → Diagnostics).
