## What the E2E does

It builds an isolated sandbox in the system temp folder: a copy of schemas, configs, tools, prompts
and the character profiles, with **synthetic coloured images** standing in for the private
references (your real images are not used). All media are generated by FFmpeg and labelled: a grey
"test handbag" image, a test-pattern MP4 per clip, a test reference video. Every job is a **test
job**; packages are stamped TEST. The app runs on its own database in the sandbox, so your data is
never touched. No provider renders anything and no paid API is called (`ANTHROPIC_API_KEY` is
removed from the server's environment).

**Flow A — Original · Talking Influencer · Female 02 · Google Flow · 16 s:**
campaign draft → handbag upload → complete campaign → job → brief → refused approvals (wrong job id,
missing header, wrong gate) → brief approval → concepts → choose → Indonesian custom script kept word
for word → refused edit of the exact script → script approval → storyboard (2 clips of 8 s) →
storyboard approval → sent through the orchestrator (n8n or direct) → AWAITING_RENDER, Flow prompts,
continuity, render sheet → **app restart, state persists** → non-video upload refused → test MP4 per
clip → contact sheet, first frame, range requests, traversal refused → failing QC refused → draft →
approval → package → DELIVERED → ZIP contents (brief, script, storyboard, prompts, manifests, QC,
history, takes, assembled edit; **no reference images**; TEST stamp) → history, approvals, costs.

**Flow B — Reference Guided · Fashion Showcase · Seedance · 10 s (smaller):** reference upload with
rights → frames + manifest → mock analysis with unknowns → brief approval → adapted concept → no
dialogue → storyboard → Seedance prompt (1 clip) → blocked until the first frame is uploaded →
AWAITING_RENDER → short take flagged by the technical check → N/A refused for an applicable check →
reject → new take → approve → TEST package.

**n8n only:** execution ids recorded, duplicate submission deduplicated, a stage failure inside a
workflow → Workflow E → job FAILED with error and execution id → bounded retry back to the failed
(approved) state → retry refused when not failed; a forged webhook without the token touches no job.

**Auth/contract:** callbacks without or with a wrong token refused, settings never return secrets,
Anthropic mode disabled without key and budget.

## Frontend

The dashboard was checked by hand in the in-app browser: dashboard, campaign → job creation, running
automatic stages, approval dialog, Script tab (concepts, exact script, timing), Prompt Studio and
Render & QC playback, no console errors. There are no automated browser (Playwright) tests yet; the
API E2E covers every action the UI calls.

## Bugs found by these tests and fixed

- E2E hung on shutdown when a download response body was not consumed (test harness).
- n8n returns `200` with an empty body when a workflow fails before its Respond node; the app now
  treats that as a failure.
- Retry could not restore an approved state (state machine treated it as a new approval).
- Missing prompt modules (natural-motion, audio-director, seedance) broke manual prompt export.
